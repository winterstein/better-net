# bn-webapp status

Vite + React companion UI, served from `app.better-net.com`. Read-only views on feedback;
unlike the extension, the whole app requires sign-in.

## Works

- **Live at `https://app.better-net.com`** — deployed and serving, with the tenant, client
  id and `https://server.better-net.com/api` all present in the served bundle. The cert and
  vhost turned out to already exist, contrary to what this file said before 2026-09-23.
- **Deploy workflow**: `.github/workflows/webapp-deploy.yml` — tests, builds, SCPs the
  bundle and swaps `/opt/betternet/webapp` on the host, triggered by pushes touching
  `bn-webapp/**`. Vite inlines `VITE_*` at build time, so the workflow refuses to build
  without all four values *and* greps the bundle to confirm they were inlined: a dropped env
  var otherwise produces a healthy looking build that 401s on every call. Its last step does
  a real HTTPS request through the vhost, and says the files are in place but unserved if no
  vhost is enabled, rather than passing quietly. No nginx or certbot commands — the deploy
  user's sudo is a narrow allowlist, and a cert must exist before its vhost is enabled or
  nginx takes every other site on the host down with it.
- Builds on **node 24 in CI, not 20**: `package-lock.json` was generated by npm 11, and the
  npm bundled with node 20 resolves vitest's nested vite peer dependency differently — it
  demands an `esbuild@0.28.2` the lockfile does not carry and fails `npm ci` outright.
- Prod build config lives in the GitHub `prod` environment as variables (all four are public
  values, so none is a secret): `VITE_AUTH0_DOMAIN`, `VITE_AUTH0_CLIENT_ID`,
  `VITE_AUTH0_AUDIENCE`, `VITE_API_BASE`. The last one is the easy one to miss —
  `app.better-net.com` serves static files and proxies nothing, so the `/api` default only
  works in dev, where Vite proxies it.
- Pages, Chunks, Analyze URL, My feedback, and staff All feedback views
- **Auth0 sign-in** (`src/auth/`): `@auth0/auth0-react`, SPA + PKCE, JWT sent as a Bearer
  header by `services/api.ts`. Tenant `better-net.eu.auth0.com`, application
  `BetterNet Webapp` (`WBF8SVYqzsxI37AbH733VNHyQgvPs5ou`), URLs registered for
  `http://localhost:3000` and `https://app.better-net.com`.
- Config in `.env.local` (gitignored), documented in `.env.example`. The API (resource
  server) `https://server.better-net.com/api` now exists in the tenant, so
  `VITE_AUTH0_AUDIENCE` is live rather than commented out — that is the setting that makes
  Auth0 issue a JWT instead of an opaque token.
- Device linking: the extension's one-time code is stashed in `sessionStorage` at startup
  (`main.tsx`) because the Auth0 redirect drops the URL fragment, then redeemed after
  sign-in. Sign-in carries `appState.returnTo`, since Auth0 only returns to the origin.
- The staff nav link only appears for staff, so nobody is invited into a 403
- `npm test` — 22 tests (`test/feedback-viewer.test.ts`), no browser needed

## Blocked

- **Nobody has completed a signed-in API call yet, in any environment.** A real localhost
  login worked and Auth0 issued a token for the right audience (confirmed in the tenant
  log), but every guarded call still 401'd — bn-server never read its `.env`, so
  `AUTH0_DOMAIN` was unset and `auth.ts` refuses all tokens when it is. That is fixed and
  deployed, so the configuration should now be right end to end; it is untested, and until
  someone signs in it stays a claim rather than a result.
- The Google connection uses **Auth0's development keys**, which the tenant log warns against
  for production: rate-limited, and the consent screen carries Auth0's logo rather than
  ours. Needs our own Google OAuth client before real users.

## Next

- Sign in at `https://app.better-net.com` and open My feedback. An empty list is a pass; a
  401 means the token is still being rejected. Whether `/api/account/me` carries an email
  also tells you the post-login Action is firing, though nothing breaks if it is not — `sub`
  is the identity and the email is only a label.
- `npx tsc --noEmit` is noisy: the symlinked `bn-extension-src` has pre-existing implicit-any
  errors. `npm run build` (vite) is the real gate and is clean.
